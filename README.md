# a little connection

a little connection explores how a chatbot companion could encourage healthier AI use and make it easier to connect with real people.

This working prototype has its own Gemini-powered chat and a companion panel. It demonstrates the experience of a future chatbot extension; it is not currently an installable extension for ChatGPT, Claude, or other websites.

[Watch the demo](https://www.youtube.com/watch?v=8oqGM6MJHeE)

## What it does

- **Optional conversation monitoring:** Users choose when to turn the companion on or off. It looks for patterns such as withdrawing from friends, relying heavily on AI for emotional support, or handing over independent decisions.
- **Gentle check-ins:** Three qualifying user messages across at least two cue categories within the latest eight messages trigger a check-in. Another eight user messages pass before detection starts fresh.
- **Balanced chatbot responses:** A check-in automatically enables guidance for more balanced replies, with a visible notice. A clearly overly validating or intimate chatbot reply instead offers the user a choice to enable adjustments. Users can also turn adjustments on manually. When adjustments are off, no app-authored behavior instructions are added to the chatbot.
- **Real human conversations:** Users write requests to a volunteer and can send multiple requests. The volunteer turns availability on, accepts a request, and replies. Pending requests and accepted conversations appear in a full-page messaging view. Volunteer replies are written by a person, not generated by AI.
- **Interest groups:** Users can explore fictional photography, music, and board-game groups, inspect their details, and save bookmarks. In this demo version, saving does not join a group.
- **Saved history:** Conversations, settings, and bookmarks remain on the computer running the app after it closes. They are not synchronized across different computers.

AI conversations and detected cues are not shared with the volunteer. Only the messages written in the human conversation are shared.

## Tools used

| Tool | What it does |
| --- | --- |
| HTML and CSS | Build the screens and their appearance. |
| JavaScript | Handles buttons, messages, and updates in the browser. |
| Node.js 24 | Runs the local server on your computer. |
| Gemini API | Generates chatbot replies and separately classifies possible cues in user messages and AI replies. The configured model is `gemini-3.5-flash-lite`. |
| `@google/genai` 2.31.0 | Google's official JavaScript library for contacting Gemini. |
| Node.js built-in modules | `http` serves the app; `fs/promises` saves data; `crypto` creates message IDs; `path` and `url` handle file locations. Tests use `node:test`, `assert/strict`, and `os`; the setup check uses `timers/promises`. |
| Local JSON files | Store demo history in `data/demo.json` and fictional group details in `public/groups.json`. No separate database service is needed. |

## Run it on your computer

### 1. Install Node.js

Download and install **Node.js 24** from [nodejs.org](https://nodejs.org/en/download). It includes **npm**, the tool used to install this project's library and start the app.

After installation, reopen your terminal or code editor. Check that it works:

```sh
node --version
npm --version
```

### 2. Download this project

On the [GitHub repository](https://github.com/forestmeows/a_little_connection), click **Code → Download ZIP**, then extract the ZIP into a folder.

Open that extracted folder in your code editor. In VS Code, choose **Terminal → New Terminal**. Make sure the terminal is in the folder containing `package.json`.

If you already have this project open, use its existing folder instead of downloading another copy.

### 3. Install the project's library

In the project terminal, run:

```sh
npm install
```

### 4. Add your Gemini API key

An API key lets the local server contact Gemini.

1. Open [Google AI Studio](https://aistudio.google.com/apikey) and create an API key in an eligible free-tier project. Do not enable paid billing for this demo.
2. In your project folder, copy `.env.example` and name the copy **`.env`**. If `.env` already exists, keep that file.
3. Open `.env` in your editor and put your key after `GEMINI_API_KEY=`:

```dotenv
GEMINI_API_KEY=paste_your_key_here
GEMINI_MODEL=gemini-3.5-flash-lite
```

4. Save the file. Keep the key private; do not upload it or show it in a recording. `.env` is excluded from Git.

Free-tier availability and request limits depend on your account and model access. The app does not automatically switch to a paid service. Use fictional, non-sensitive conversations: Gemini's free tier may use submitted content to improve Google products.

### 5. Start the app

Run:

```sh
npm start
```

Keep that terminal open, then visit these addresses in your browser:

| Page | Address |
| --- | --- |
| User chatbot and companion | http://127.0.0.1:3000/ |
| User's volunteer conversations | http://127.0.0.1:3000/messages |
| Volunteer screen | http://127.0.0.1:3000/volunteer |

The app runs on your own computer. Internet access is required for Gemini replies and monitoring.

### 6. Try the features

1. Open the user page and click **Companion**. Turn on **Companion monitoring** before sending messages you want checked. **Response adjustments** is a separate control.
2. Use **Send a new request** to write a fictional message to a volunteer.
3. Open the volunteer page in a second browser window. Turn availability on, select the request, click **Accept request**, and type a reply.
4. Return to the user page and open **Current chats** to see the accepted conversation and reply. You can create additional requests to test several separate conversations with the same demo pair.
5. In the companion panel, explore the interest groups, expand their details, and save one. It will appear under **Saved interests**.

To stop the app, press **Ctrl+C** in the terminal running `npm start`. Run `npm start` again whenever you want to reopen it. Volunteer availability resets to off after a server restart; saved history and bookmarks remain.

## Prototype boundaries

This is an **adult-only demonstration for ages 18–25**, using one local user role and one volunteer role. There are no separate user accounts, real volunteer matching, or staffed nonprofit service. Community groups, contacts, and events are fictional; membership and group chat are not implemented.

The detection is experimental, not a diagnosis of dependence or a validated wellbeing assessment. This is not an emergency-support service. Planning documents and the code guide are in [`devpost/`](devpost/), including the [app map](devpost/app-map.html).
